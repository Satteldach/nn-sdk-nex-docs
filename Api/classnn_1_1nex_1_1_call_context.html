Detailed Description

Root class for the asynchronous process management classes.

When NEX runs asynchronous processes such as those for communicating with a server, it passes the CallContext class or one of its subclasses to the parameter of the asynchronous function. (An example of a subclass is the ProtocolCallContext class, which is created for communicating with a server.) You can also use the CallContext class to get information about the states and results of asynchronous processes, to cancel or reset processes, and to configure timeouts.

enum nn::nex::CallContext::State

Enumerates the states of CallContext.

When an asynchronous process starts, the state changes from Available to CallInProgress. When that process ends, the state changes to CallSuccess, CallFailure, or CallCancelled.

CallInProgress

void nn::nex::CallContext::RegisterCompletionCallback ( CompletionCallback  pfCompletionCallback,
const UserContext &  oContext,
bool  bAddToEnd = true 
)

Sets the callback function to be invoked when this CallContext has completed.

The configured callback is invoked when this CallContext enters its completed state. Using this callback, you can avoid polling to determine whether the CallContext has completed.

You can call this function more than once to register multiple callbacks. By default, callbacks are invoked in the order that they were registered; the first callback to be registered is the first callback to be invoked. If you want to change this order, you need to set the bAddToEnd parameter when you register your callback.

Do not call NEX blocking functions from inside the callback function.

Parameters
[in]pfCompletionCallbackA pointer to the completion callback to be invoked.
[in]oContextThe UserContext to pass to the callback function that is invoked.
[in]bAddToEndIf true (the default), the callback is added to the end of the list. If false, it is added to the front of the list.

bool nn::nex::CallContext::Wait ( uint32_t  uiTimeout = WAIT_INFINITE_TIMEOUT)

Waits and continues internal processing until the asynchronous process has completed or the timeout was exceeded.

You can call this function when the CallContext State is CallInProgress. This function calls the Scheduler::Dispatch() function internally until asynchronous processing completes or times out.

If the timeout elapses, the SYSTEMERROR_GEN_TIMEOUT error results. Asynchronous processing continues even after a timeout occurs, so the resource specified for the asynchronous processing out parameter cannot be released. Explicitly call the CallContext::Cancel() function when you want to release the resource specified for the out argument.

Parameters
[in]uiTimeoutThe maximum amount of time (in milliseconds) to wait. By default, uiTimeout is infinitely large.
Returns
Returns true if asynchronous processing is complete, and returns false if the timeout was exceeded. If this function returns false, the return value of the CallContext::GetOutcome function is undefined.
See also
State, CallContext::GetOutcome
bool nn::nex::CallContext::WaitWithoutDispatch ( uint32_t  uiTimeout = WAIT_INFINITE_TIMEOUT)

Waits until the asynchronous process has completed or the timeout was exceeded.

You can call this function when the CallContext State is CallInProgress. Control does not return until the asynchronous process has completed or the timeout was exceeded. Unlike CallContext::Wait(), this function does not internally call Scheduler::Dispatch(). For internal processing to proceed, a function like Scheduler::Dispatch() must be called from another thread. Even when the NEX library is in thread-unsafe mode, you can call this function at the same time as Scheduler::Dispatch() or any other function.

Even if the timeout was exceeded, you cannot release the out argument because the asynchronous process will continue. Explicitly call the CallContext::Cancel() function when you want to release the resource specified for the out argument.

Parameters
[in]uiTimeoutThe maximum time to wait (in milliseconds). The default uiTimeout is infinite.
Returns
Returns true if asynchronous processing has completed, and returns false if the timeout was exceeded. If this function returns false, the return value of the CallContext::GetOutcome function is undefined.

State, CallContext::GetOutcome
bool nn::nex::CallContext::Cancel ( )

Cancels the asynchronous process associated with this CallContext.

This cancels any asynchronous process associated with the CallContext that has not yet been run. After this function returns, you can free the value you set for the out argument when you started asynchronous processing.

There is no way to cancel or check on the progress of running processes. If, for example, you cancel a process that has already sent a server some kind of request, the server will process that request despite the fact that the sending process was canceled. The result will then be ignored by the caller even if it is received.

Use this primarily to release out arguments set for asynchronous processes with results you consider safe to ignore.

This function returns true and its asynchronous processing result is QERROR(Core, Cancelled) when it has canceled an asynchronous process. This function returns false when it is used to cancel a process whose state is not CallInProgress and the process will not be canceled.


Return Values

true: Asynchronous processing was canceled. (When its state was CallInProgress.)

false: Attempted to cancel an asynchronous process that has not yet started. (When its state was Available.) Or asynchronous processing had already completed. When its state was CallSuccess, CallFailure, or CallCancelled.)

template<typename TCallback >
void nn::nex::CallContext::RegisterCompletionCallbackGeneric ( TCallback &&  callback,
bool  deleteCallbackAfterCall = false,
bool  bAddToEnd = true 
)

Sets the callback to be invoked when this CallContext has completed.

The configured callback is invoked when this CallContext enters its completed state. Using this callback, you can avoid polling to determine whether the CallContext has completed.

callback can be a lambda expression, functor, or a pointer to a function that takes a CallContext* as an argument. If you use this together with AddCallContextArgumentAdapter(), you can pass a function that takes no arguments.

When passing a functor as an argument, you can choose to use a value/reference or a pointer; these result in different behavior. If you provide a value/reference type, the functor will be internally copied or moved before it is passed to the callback to use. As a result, you can immediately destroy the specified object after calling this function. If you provide a pointer to an object, the callback will access that object directly through the pointer. As a result, the caller must preserve this functor until the callback has been invoked.

You can call this function more than once to register multiple callbacks. By default, callbacks are invoked in the order that they were registered; the first callback to be registered is the first callback to be invoked. If you want to change this order, you need to set the bAddToEnd parameter when you register your callback.

By setting deleteCallbackAfterCall equal to true when you pass a pointer to a functor in callback, you can automatically delete the callback functor after it has been invoked. If you want to destroy callback using your application's own custom memory deallocation routine, you can call this function again with a new functor encapsulating that code.

Do not call any NEX blocking functions within your callback.

Parameters
[in]callbackA lambda expression, functor, or function pointer to use as a callback.
[in]deleteCallbackAfterCallWhether to automatically delete callback after it has completed.
[in]bAddToEndIf this is the default value of true, the callback is added to the end of the list. If false, it is added to the beginning of the list.
