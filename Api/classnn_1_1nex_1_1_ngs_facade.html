Detailed Description

Conducts login processes.

The Scheduler::Dispatch() function must be called periodically as long as a NgsFacade object exists.

Constructor & Destructor Documentation

virtual nn::nex::NgsFacade::~NgsFacade ( )
virtual

Destructor.

When the status is either logging in, logged in, or logging out, the NgsFacade::Terminate() function is called inside the destructor and blocks until the library transitions to offline status. We recommend calling NgsFacade::Terminate() function before the destructor is called.

Logs in.

Logs in to the NGS (Nintendo Game Server).

A network service account must be created prior to logging in to NGS.

You must initialize the nn::account, nn::nifm, and nn::socket libraries before calling this function.

This function logs in to NGS using the specified network service account ID and the network-service account ID token. For more information about getting the network service account ID and the ID token, see the sample code and the NintendoSDK documentation.

Do not use ProtocolCallContext::SetTimeout() and ProtocolCallContext::Cancel() to control asynchronous processing in this function. Use the argument to specify the timeout time, and if you want to cancel the login process, use the NgsFacade::Terminate() function to do so.

Use the CallContext::GetState() function to determine whether the asynchronous process succeeded or failed. If it failed, use either the GetLastLoginNnResult() function to get the nn::Result value or the GetLastLoginErrorCodeStruct() function to get the network error code. Do not use CallContext::GetOutcome() to get the result.

After login succeeds, the NEX library sends a keep-alive packet to the game server. If 30 seconds elapse without a keep-alive response from the game server, the library's internal status automatically transitions to offline. When this happens, perform finalization in the application and call the NgsFacade::Logout() or NgsFacade::Terminate() function. Get the library's internal status with the IsConnected() function.

On the game server side, if 30 seconds elapse without receiving a keep-alive packet from a client, that client is treated as logged out.

Parameters
[in,out]pContextCall information. Do not use this object to cancel or set the length of timeouts.
[in]gameServerIdGame Server ID.
[in]pAccessKeyAccess key for the game server.
[in]nsaIdThe network service account ID.
[in]pNsaIdTokenThe null-terminated network service account ID token.
[in]uiTimeoutTimeout (in milliseconds). The default value is 30 seconds.


Return Values

QSUCCESS(Core,Success): Successfully started the login process.

QERROR(Core,InvalidArgument): Invalid parameter.

QERROR(Core,OperationAborted): The system is currently either logging in, logging out, terminating, or already online.

bool nn::nex::NgsFacade::TestConnectivity ( ProtocolCallContext *  pContext)

Runs a test of Internet connectivity.

Runs an Internet connectivity test by communicating with the game server. If you can communicate with a game server that is operating normally, this function's asynchronous process always returns success. You do not need to wait for this function's asynchronous process to complete. It causes no problem to treat the connectivity test as failed if it does not complete within the time specified by the application (about two or three seconds).

Making periodic calls to this function is prohibited. Use this function to determine whether the disconnection was caused by the remote client or the local client during peer-to-peer communications. Use NgsFacade::IsConnected() to check whether the communication state with the server is maintained.

This function can only be used when logged in to the game server.

Parameters
[in,out]pContextCall information.


Return Values

true: Successfully started asynchronous processing.

false: Cannot start asynchronous processing because the status of the specified pContext is CallContext::CallInProgress. This value indicates that it is being used in other asynchronous processing. Because this is a programming error, it causes an assertion failure and halts execution on non-release builds.

bool nn::nex::RendezVous::GetGameServerTime ( DateTime *  pServerTime) const
inherited

Gets the game server time (UTC).

You can get this information after logging in to the game server. The value can still be obtained even after logging out. Calculates the current time based on the time obtained from the game server when logging in.

The main causes of the time being off are: game server latency at the time of login when getting the game server time, one-way latency from the game server, and client latency when calling Scheduler::Dispatch(). In addition, the game server clock is only as accurate as NTP synchronization, so it may be off from UTC by as many as several hundred milliseconds. To distribute the load, each station may connect to a different game server. In such cases, the times are not guaranteed to be the same.

The accuracy of the time also depends on the system clock, so accuracy cannot be guaranteed if a number of days have passed since logging in.

Not recommended:
We do not recommend using this function. The API has been left for compatibility. Instead, use the SDK's network clock (nn::time::StandardNetworkSystemClock).
Parameters
[out]pServerTimeThe server time.
Returns
Returns the execution result.


Return Values

true: Success.

false: Failure. Never logged in to the game server. Or pServerTime is NULL.

qResult nn::nex::BackEndServices::IsConnected ( ) const
inherited

Gets the status of the connection to the game server.

Gets the status of the connection to the game server. The NgsFacade::Logout() function must be explicitly called when this function returns anything other that QSUCCESS(Core, Success) after logging in to the game server. Calling this function in every frame has no effect on performance. This function will return QSUCCESS(Core, Success) as soon as the login is successful.

The connection goes offline when the network connection is dropped or the application cannot communicate with the server for a specified amount of time.

QERROR(RendezVous, ConnectionDisconnected) is returned when not connected to the game server.

To let the user know that the connection with the game server was lost, convert to a nn::Result object using qResult::GetNnResult(), and then pass that object to the error display function. The Communication error has occurred message appears.

If the same account is used to log in from another device, the original device is disconnected from the game server. When this happens, IsConnected() returns QERROR(RendezVous, ConnectionDisconnectedForConcurrentLogin) on the original device. If you pass this value to the error display function, a message appears stating that you have been disconnected from the server because you logged in from another device.


Return Values

"QSUCCESS(Core, Success)": Connecting to game server (online).

QERROR(RendezVous, ConnectionDisconnected): Offline.

QERROR(RendezVous, ConnectionDisconnectedForConcurrentLogin): Offline because another device logged in.

bool nn::nex::BackEndServices::Terminate ( CallContext *  pContext)
inherited

Terminates NgsFacade, and puts in a state where it can be deleted.

This function can be called while online, offline, logging in, or logging out, so termination of the asynchronous process and transition to offline status are guaranteed.

When the status is either logging in, logged in, or logging out, NgsFacade::Terminate is called by the NgsFacade destructor and blocks until the status transitions to offline. We recommend calling NgsFacade::Terminate before destroying NgsFacade.

Before calling this function, make sure that you run the Unbind() function of a class derived from ServiceClient (such as MatchmakeExtensionClient or NATTraversalClient) and perform the deletion process.

Asynchronous processing can take a long time when the local device is not connected to a network, so you can set the mode to forced termination mode using the Core::SetTerminateImmediately() function.

Parameters
[in,out]pContextCall information.


Return Values

true: Successfully started asynchronous processing.

false: Cannot start asynchronous processing because the status of the specified pContext is CallContext::CallInProgress. This value indicates that it is being used in other asynchronous processing. Because this is a programming error, it causes an assertion failure and halts execution on non-release builds.
