Detailed Description

VSocket is a UDP socket-like interface to a low-level communication library.

VSocket allows you to use third-party network engines for peer-to-peer communication between clients while continuing to take advantage of NEX server features, NAT traversal, encryption, and spoofing detection. We expect third-party network engines to be updated to use the VSocket API instead of the socket API.

Like UDP, VSocket is a connectionless protocol that does not guarantee delivery or ordering. Because most networked devices are located behind a NAT router, NAT traversal must be done before starting VSocket communications. Applications must send keepalive signals to preserve routers’ NAT table entries along the path between two devices.

bool nn::nex::VSocket::Bind ( uint8_t  uiVPort)

Binds a VSocket to the specified virtual port.

If you create multiple VSocket objects and bind them to different virtual ports, they will all use the same UDP socket internally. Data is multiplexed as it is sent to and received from the virtual port number. A single application can use up to 15 virtual ports. The VSocket::Open() function must be called before calling this function.

Parameters
[in]uiVPortThe virtual port to use when sending and receiving data. Specify a number from 1 to 15.
Return Values

true: Success.

false: Failure. One of the following reasons. VSocket::Open() was not called in advance. VSocket::Bind() has already been called. The specified uiVPort is not in the range from 1 and 15.

Parameters

[in]uiBufferSizeThe size of pBuffer. You can specify a number from 1 to VSocket::MAX_DATA_SIZE.
[in]oDestinationAddressThe recipient’s address data. You must specify the VSocket virtual port number as well as an IP address and port number found through NAT traversal.

VSocket::PacketBufferFull: Data cannot be sent because the send/receive buffer is full.

static bool nn::nex::VSocket::ProbeStations ( CallContext *  pContext,
StationProbeList *  preflstStationProbe,
uint32_t  ui32Timeout = 0,
bool  bWaitForAllResult = false 
)
static

Traverse NAT.

You must call ConnectivityManager::StartNATSession() before this function. The previous NAT traversal results saved in preflstStationProbe (round-trip times and statistical data) are cleared when this function is called. Do not use CallContext::SetTimeout() and CallContext::Cancel() to control asynchronous processing in this function. Timeouts are automatically configured within this function. If asynchronous processing is successful, NAT traversal succeeded for all of the specified devices. The following results may be returned as a result of asynchronous operation.

  • QERROR(Core, InvalidSequence): ConnectivityManager::StartNatSession() was not called in advance.
  • QERROR(Transport, NatTraversalError): NAT traversal failed for at least one device. (Including failures caused by timeouts.) By setting bWaitForAllResult equal to true and checking preflstStationProbe, you can determine which device failed.
Parameters
[in,out]pContextCall information.
[in,out]preflstStationProbeSpecifies information about the devices to find through NAT traversal. When asynchronous processing ends, this contains statistical data, round-trip times, and values indicating whether NAT traversal was successful for each device.
[in]ui32TimeoutThe specified value is ignored. Specify a value of 0. Timeouts are automatically configured within this function.
[in]bWaitForAllResultIf false, asynchronous processing immediately ends when NAT traversal fails for any device. If true, asynchronous processing continues until NAT traversal has definitively succeeded or failed for each device. Set to false when NAT traversal must be successfully completed for all devices. This parameter applies to server-client (star) and full mesh network topologies. Set to true if you only want to communicate with devices for which NAT traversal has succeeded. This parameter applies to special network topologies in which (for example) devices communicate through intermediate relays when NAT traversal fails.


Return Values

true: Successfully started asynchronous processing.

false: Cannot start asynchronous processing because the status of the specified pContext is CallContext::CallInProgress. This value indicates that it is being used in other asynchronous processing. Because this is a programming error, it causes an assertion failure and halts execution on non-release builds.
