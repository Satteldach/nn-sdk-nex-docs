Detailed Description

Class that sets the thread mode in which the system operates. Also sets the NgsFacade destruction mode.

This class is instantiated when an NgsFacade, VSocket, MatchmakeExtensionClient, or other client object is created. When these objects are all destroyed, so is the Core object.

After creating a Core object, use Core::SetThreadMode() to set the thread mode.

Member Enumeration Documentation

enum nn::nex::Core::ThreadMode

Enumerated type representing the thread modes. Used as an argument for the Core::SetThreadMode() function.

A value other than Core::ThreadModeUndefined must be set.

Enumerators
ThreadModeUndefined 

This value is the default.

Works the same as Core::ThreadModeInternal.

ThreadModeSafeTransportBuffer 

Sets the mode to thread-safe transport buffer thread mode. The blocking time of the dispatch process (which is long when sending and receiving) is improved by sending and receiving using a transport buffer thread in the library. Mutual exclusion is enabled within the library and most API functions are thread-safe, with some exceptions. For more information, see Initialization Settings (Thread Models, Exclusive Control, and Local Communication) in the NEX Programming Manual. You must run the Scheduler::Dispatch() function periodically on the application side.

ThreadModeUnsafeTransportBuffer 

Sets the mode to thread-unsafe transport buffer thread mode. The blocking time of the dispatch process (which is long when sending and receiving) is improved by sending and receiving using a transport buffer thread in the library. Mutual exclusion is disabled within all but some parts of the library and processing is faster. Locking is not performed, so use all the NEX APIs from a single thread or perform locking on the application side, as appropriate. You must run the Scheduler::Dispatch() function periodically on the application side. This thread mode is superior in terms of both processing speed and blocking time.

ThreadModeUnsafeUser 

Sets the mode to thread-unsafe user thread mode. User threads are used for both dispatching and communication processes. Mutual exclusion inside the library is disabled to improve processing speed. Locking is not performed, so use all the NEX APIs from a single thread or perform locking on the application side, as appropriate. You must run the Scheduler::Dispatch() function periodically on the application side. This thread mode is superior in terms of processing speed. However, socket processing can block for several milliseconds, so call NEX APIs on a separate thread from the main thread.

ThreadModeInternal 

Sets the mode to internal thread mode. Dispatching and communication processes are both handled automatically by threads inside the library. Mutual exclusion is enabled within the library and most API functions are thread-safe, with some exceptions. Depending on when the application calls NEX API functions, those function calls may block for a length of time. To avoid this issue, use Core::ThreadModeInternalTransportBuffer.

ThreadModeInternalTransportBuffer 

Sets the mode to internal transport buffer thread mode. Dispatching and communication processes are both handled automatically by threads inside the library. Mutual exclusion is enabled within the library and most API functions are thread-safe, with some exceptions. The blocking time of the dispatch process (which is lengthy when sending and receiving) is improved by sending and receiving using a transport buffer thread in the library. This reduces the time that Scheduler::SystemLock() is maintained internally, which reduces the blocking time when the application makes calls to the various NEX functions.

void nn::nex::Core::SetTerminateImmediately ( bool  bTerminate)

Sets the mode to terminate immediately.

Depending on the internal library state and the network state, the NgsFacade::Terminate() function and NgsFacade destructor sometimes block for a long time when finalizing NEX. You can shorten the time for these processes by setting the mode to terminate immediately.

Because the normal process of network disconnection is not performed, the local station may sometimes seem to peers to be disconnected from the network because of a keep-alive timeout. For this reason, do not set this mode for normal termination sequences. All functions that communicate with the server will fail.

This operation can be performed by calling the nn::nex::Core::GetInstance() function and then the SetTerminateImmediately() function.

This function can be used to destroy the entire NEX instance when shutting down or when not connected to a network.

The default termination mode is normal termination. This setting is maintained in each Core instance. The mode is set to terminate normally when the station logs in to the game server.

Parameters
[in]bTerminateSpecify true to set the mode to terminate immediately. Specify false to return to normal mode.

Determines whether internal thread mode is enabled.

Internal threads are threads that NEX handles internally. This function returns true if you specified Core::ThreadModeInternal or Core::ThreadModeInternalTransportBuffer when you called the Core::SetThreadMode() function. You cannot use this function until you have created a NEX Core object.
