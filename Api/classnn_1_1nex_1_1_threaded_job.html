template<typename TCallback >
bool nn::nex::ThreadedJob::Start ( CallContext *  pContext,
TCallback &&  threadedCallback,
bool  deleteCallbackAfterCall = false 
)

Asynchronously runs a task on a new thread.

When called, this function creates a single thread from which threadedCallback is invoked. threadedCallback returns when the asynchronous task is complete and stores its result in pContext.

threadedCallback can be a lambda expression, functor, or function pointer that takes no arguments and returns either a qResult or Boolean value. You can call GetOutcome() on pContext to get the qResult value returned by threadedCallback. threadedCallback can return qResult(true), qResult(false), or the qResult object obtained from CallContext::GetOutcome() as the result of calling various asynchronous NEX functions. You can use QRESULT_ERROR(<value greater than qResultFacility::FirstUserFacility>, <0-0xFFFF>) if you want to return application-defined errors. If threadedCallback returns a Boolean value, the pContent GetOutcome() method returns QSUCCESS(Core, Success) when that value is true and QERROR(Core, Unknown) when that value is false.

When passing a functor as an argument, you can choose to use a value/reference or a pointer; these result in different behavior. If you provide a value/reference type, the functor is internally copied or moved before it is passed to the callback to use. As a result, you can immediately destroy the specified object after calling this function. If you provide a pointer to an object, the callback will access that object directly through the pointer. As a result, the caller must preserve this functor until the callback has been invoked.

By setting deleteCallbackAfterCall equal to true when you pass a pointer to a functor in threadedCallback, you can automatically delete the functor after it has been invoked.

You can call this function as many times as you like on a single ThreadedJob object regardless of whether you started an asynchronous task that has not yet finished. You can destroy a ThreadedJob object before an asynchronous task has completed.

After calling this function, you must wait for the threadedCallback invoked from a new thread to finish before you can call CallContext::Cancel(). Scheduler::Dispatch() blocks until threadedCallback has completed.

If you are calling NEX functions from multiple threads in parallel, note that the NEX library must be using thread-safe mode.

Parameters
[in,out]pContextAn object for managing the execution state of an asynchronous task.
[in]threadedCallbackThe callback to be invoked from the new thread.
[in]deleteCallbackAfterCallWhether threadedCallback can be automatically deleted after it has finished running.
Returns
Whether the asynchronous task was started successfully. It will fail to be started and the return value will be false only if pContext is CallContext::CallInProgress.
