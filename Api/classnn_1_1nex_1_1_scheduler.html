Detailed Description

Schedules the execution of jobs.

The Scheduler class is used for executing NEX jobs. Make sure to execute jobs by periodically calling the Scheduler::Dispatch or Scheduler::DispatchAll function from the application.

This class is a singleton. Instances are automatically created and released by the system.

Member Function Documentation

void nn::nex::Scheduler::DispatchAll ( )

Executes all registered jobs.

If this function is called, all jobs registered in the scheduler execute until it is empty. If many jobs have been registered, there is a chance that a lot of CPU time will be consumed. To prevent fluctuations in the frame rate, use the Dispatch function, which can specify timeouts.

Make sure to call this function periodically.

Careful attention is required when executing a process (such as loading a file while the screen display is off) that performs extreme blocking in the main thread. If processing in the main loop is backlogged and jobs cannot be executed, sending and receiving of messages could be delayed, making it seem that a timeout has occurred.

Nothing happens if calling this function while using one of the internal thread modes.

size_t nn::nex::Scheduler::Dispatch ( uint32_t  uiDispatchTimeout,
uint32_t  uiFlags = 0 
)

Executes registered jobs with the set timeout.

Executing this function executes registered jobs. However, if the specified timeout elapses, this function halts job execution and returns control to the game. Jobs that did not execute will be executed the next time Dispatch() is called.

Make sure to call this function periodically.

Careful attention is required when executing a process (such as loading a file while the screen display is off) that performs extreme blocking in the main thread. If processing in the main loop is backlogged and jobs cannot be executed, this could impact the sending and receiving of messages and make it seem that a timeout has occured.

Also, if the timeout specified to this function is too short, the number of jobs that continue to be registered will become larger than the number of jobs that can be executed. At this time, job execution will not advance no matter how much time elapses, and the system may fall into the stated described above. Adjust the timeout period and traffic volume to meet application specifications. You can use Scheduler::GetReadyJobsSize() to get the number of remaining jobs.

The timeout is not an accurate numeric value. Note that there is a possibility of going over the time specified depending on the number of jobs, their content, and their timing.

Calls to this function do nothing when internal threads are in use.

Parameters
[in]uiDispatchTimeoutSpecifies the timeout in milliseconds. If you specify a value of 0, this will behave like Scheduler::DispatchAll() and dispatch all jobs.
[in]uiFlagsSpecifies the job execution method in a bit flag format. (Default is no flag.) For more information about job execution methods, see DispachFlag.
Returns
The return value is always 0.

static void nn::nex::Scheduler::SetInternalThreadInvokeDispatchOnEvent ( bool  invokeDispatchOnEvent)
static

Determines whether the internal thread calls the Scheduler::Dispatch() function the moment an event occurs.

This setting is used if you specified Core::ThreadModeInternal or Core::ThreadModeInternalTransportBuffer when calling the Core::SetThreadMode() function. If invokeDispatchOnEvent is set to false, the internal thread runs Scheduler::Dispatch() periodically at the interval specified by Scheduler::SetInternalThreadDispatchInterval().

If invokeDispatchOnEvent is set to true when Core::ThreadModeInternal is used, in addition to periodically running Scheduler::Dispatch(), Scheduler::Dispatch() is automatically run the moment a job is submitted. As a result, processes such as RMC sending are performed without delays.

If invokeDispatchOnEvent is set to true when Core::ThreadModeInternalTransportBuffer is used, Scheduler::Dispatch() is automatically run when jobs are submitted or packets are received. Internal processing is performed without delays because the interval set in Scheduler::SetInternalThreadDispatchInterval() is ignored, and Scheduler::Dispatch() is run when necessary. In cases where there is frequent communication, the CPU load may increase.

Configure before initializing NEX. The default is false.
