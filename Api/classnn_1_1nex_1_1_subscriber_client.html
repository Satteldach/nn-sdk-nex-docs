Posts content to a topic.

Posts a single piece of content to one or more topics.

However, the topics feature is deprecated. If the feature is eliminated, the function will return NotImplemented as the Result instance.

The following results may be returned as a result of asynchronous operation. Pass errors to the error viewer applet. Errors must be removed during debugging.

  • QERROR(Subscriber, InvalidArgument): No topics have been specified. Invalid topic format.
  • QERROR(Subscriber, OverLimit): The length of the message to post exceeds SubscriberConstants::MAX_CONTENT_MESSAGE_LEN. The size of the binary data to post exceeds SubscriberConstants::MAX_CONTENT_BINARY_SIZE. The reserved topic number exceeds SubscriberConstants::NUM_RESERVED_TOPICS. The number of topics to which to post the content exceeds SubscriberConstants::MAX_POST_CONTENT_TOPIC_SIZE.

bool nn::nex::SubscriberClient::GetContent ( ProtocolCallContext *  pContext,
const SubscriberGetContentParam &  param,
qVector< SubscriberContent > *  contents 
)

Gets the content posted in a topic.

Gets the content posted in a topic in descending order by content ID. Content IDs are issued in the order that the content is posted and are strictly increasing. The post date and time included in the content may be off by several seconds, however. Note that these time stamps may not reflect the exact order in which content was posted. Content with a smaller ID than the content with the largest ID that was obtained the last time content was retrieved may be inserted later due to differences in processing time on the server.

In rare cases, this function may be called with a frequency outside of the call frequency range specified in the guidelines. For the limits on call frequency for this function, see the guidelines. When polling, set the SubscriberGetContentParam::SetMinimumContentId() function so you do not get the same content that was retrieved before, and get no more than 20 posts from any one topic at a time. When the application transitions to a scene where the obtained information is not used, stop polling and avoid unnecessary access as much as possible.

However, the topics feature is deprecated. If the feature is eliminated, the function will return NotImplemented as the Result instance.

The following results may be returned as a result of asynchronous operation. Pass errors to the error viewer applet. Errors must be removed during debugging.

  • QERROR(Subscriber, InvalidArgument): Invalid topic format. Specified 0 as the size to get.
  • QERROR(Subscriber, OverLimit): The reserved topic number exceeds SubscriberConstants::NUM_RESERVED_TOPICS.
  • QERROR(Core, NotImplemented) : Invalid topic format.

Deletes content.

Deletes content in the specified topics. If multiple topics were specified when the content was posted, you must specify all of those topics to delete the content from all of them. If you do not specify one or more of the topics that were specified when the content was posted, the content will not be deleted from those topics. This function can only delete content that was posted by the local user. If no content is found in the specified topics, they are ignored and the function ends successfully.

However, the topics feature is deprecated. If the feature is eliminated, the function will return NotImplemented as the Result instance.

The following results may be returned as a result of asynchronous operation. Pass errors to the error viewer applet. Errors must be removed during debugging.

  • QERROR(Subscriber, PermissionDenied): This content was not posted by the local host.

bool nn::nex::SubscriberClient::UpdateUserStatus ( ProtocolCallContext *  pContext,
qVector< SubscriberUserStatusParam > &  params,
bool  isNotify = false 
)

Updates the local host status.

This updated status is shared with other users.

The status is specified in a format that associates binary data to a numeric key, as SubscriberUserStatusParam. Specify a numeric value in the range from 0 to SubscriberConstants::STATUS_KEY_SIZE - 1 as the key. The maximum amount of binary data representing the status is SubscriberConstants::MAX_STATUS_BINARY_SIZE bytes. Design a binary data structure, using a format that can associate with multiple statuses to associate them with a single key, even when the timing for updating and getting those statuses is the same.

If isNotify is true and the status is updated, notifications are sent to friends within the range for which the user has set public presence. Send this notification when you want to apply updates to friend status on an earlier schedule. In such cases, the recipients of the notifications must use SubscriberClient::GetFriendUserStatuses() or SubscriberClient::GetUserStatuses() to get statuses, as needed. Notifications are NotificationEvents::UserStatusUpdatedEvent events. You can only get the principal ID for users with updated statuses.

The following results may be returned as a result of asynchronous operation. Pass errors to the error viewer applet. Errors must be removed during debugging.

  • QERROR(Subscriber, InvalidArgument): No status is specified. Multiples of the same numeric value were specified as the key for the specified status.
  • QERROR(Subscriber, OverLimit): The numeric value for the key to the specified status is out of range. The size of the binary data for the specified status exceeds the maximum.

qResult nn::nex::SubscriberClient::GetFriendUserStatuses ( qVector< SubscriberUserStatusInfo > *  infos)

Gets the cached friend status.

Because the status is returned from obtained caches, no communication occurs during the call.

Before calling this function you must use EnableFriendUserStatusesCache() to enable the cache. Sometimes no friend statuses are obtained because you cannot get statuses from the server immediately after enabling the cache. Enable the cache using EnableFriendUserStatusesCache() and then use an appropriate interval that will allow you to get values when calling GetFriendUserStatuses().

The friends that you can get are users logged in to the same game server who share their status using SubscriberClient::UpdateUserStatus(). However, the status is not be available when users have set their presence to be private using the System features, even if they are sharing their status with SubscriberClient::UpdateUserStatus().

When an error occurs during internal communication, that error is returned as the return value for this call. If an error occurs, the previous update remains in force and the cache is not updated. When this happens, log in again after displaying the error using the error viewer applet. Then call EnableFriendUserStatusesCache() again to restart communication.

Parameters
[out]infosThe friend status. The statuses for all friends are obtained.
Returns
The result of the asynchronous communication process the last time communication was conducted.


Return Values

"QSUCCESS(Core, Success)" Asynchronous communication was successful.

"QERROR(Core, InvalidSequence)" Returned if friend status cache is not enabled. (This error is a programming error.)


Return Values
"QERROR(Subscriber, OverLimit)" Returned if more than 100 users among friends you are getting the status for have all updated their status at the same time (that is, within the same period of about one minute).


Return Values
Other communication error

uint32_t nn::nex::SubscriberClient::GetUserStatusRevision ( ) const

Returns the revision number for the cached friend status.

Returns the value that is incremented each time the cache updates. If the value overflows, it returns to 0, and is incremented again. You can easily determine cache updates from changes in this value.

Note that the update result and friend status may be identical to what they were prior to the update. If monitoring changes is required, after detecting an update using the return value of this function, compare the friend status to what it was previously in the application to determine whether it has changed.

Returns
The revision number for the friend status. If the cache for friend statuses is not enabled, the function returns 0.
bool nn::nex::SubscriberClient::GetFriendUserStatuses ( ProtocolCallContext *  pContext,
qVector< SubscriberUserStatusInfo > *  infos

Gets the friend status.

The friends that you can get are users logged in to the same game server who share their status using SubscriberClient::UpdateUserStatus(). However, the status is not be available when users have set their presence to be private using the System features, even if they are sharing their status with SubscriberClient::UpdateUserStatus().

The amount of data that is obtained during communication increases in size when the number of statuses the server is sharing is large and when many friends are in the vicinity of the user. For this reason, only get needed user statuses from SubscriberClient::GetUserStatuses() without calling this function at a high frequency.

Do not call this function from the application when the cache is enabled. This function is called by the library to update the cache. As a result, there is a risk that the guidelines will be exceeded when you also call this function from the application.

void nn::nex::SubscriberClient::EnableFriendUserStatusesCache ( )

Enables the friend status cache.

Enabling the status cache results in periodic communication which caches the obtained friend statuses. Call GetFriendUserStatuses() after this call to get statuses from the cache. Disabled by default.

When enabled, periodic communication stops when an error occurs. You can use GetFriendUserStatusesCacheLastResult() to check whether an error has occurred. Call this function again after resolving the cause of the error to resume communication.

You might not be able to get statuses after this call, even when calling GetFriendUserStatuses() immediately afterward, because communication occurs for caching as a result of this call.

void nn::nex::SubscriberClient::DisableFriendUserStatusesCache ( )

Disables the friend status cache.

Periodic communication for the status cache is stopped and the cache of obtained friend statuses is destroyed. Disabled by default.

bool nn::nex::SubscriberClient::GetFriendUserStatusesCacheMode ( )

Determines whether friend status is set to be cached.

If true is returned, EnableFriendUserStatusesCache() has been called and the friend status cache is enabled. If false is returned, the friend status cache is disabled. You cannot get statuses from GetFriendUserStatuses().


Return Values

true: Enabled.

false: Disabled.

qResult nn::nex::SubscriberClient::GetFriendUserStatusesCacheLastResult ( )

Gets the processing results during server communication when the friend status cache is enabled.

Because the system performs periodic communication when the friend status cache status cache is enabled, use this function as needed to verify the processing results for server communications. QSUCCESS(Core, Success) is returned when communication calls are occurring normally.

When an error occurs during internal communication, that error is returned as the return value for this call. If an error occurs, the previous update remains in force and the cache is not updated. When this happens, log in again after displaying the error using the error viewer applet. Then call EnableFriendUserStatusesCache() again to restart communication.

Returns
QERROR(Core, InvalidSequence) is returned when the friend status cache was not enabled as a processing result for asynchronous communication the last time it occurred.
