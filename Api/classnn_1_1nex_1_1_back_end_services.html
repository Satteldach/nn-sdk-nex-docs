Detailed Description

Class for managing connections with the game server. Use an NgsFacade class that inherits this class.

Member Function Documentation

qResult nn::nex::BackEndServices::IsConnected ( ) const

Gets the status of the connection to the game server.

Gets the status of the connection to the game server. The NgsFacade::Logout() function must be explicitly called when this function returns anything other that QSUCCESS(Core, Success) after logging in to the game server. Calling this function in every frame has no effect on performance. This function returns QSUCCESS(Core, Success) as soon as the login is successful.

The connection goes offline when the network connection is dropped or the application cannot communicate with the server for a specified amount of time.

QERROR(RendezVous, ConnectionDisconnected) is returned when not connected to the game server.

To let the user know that the connection with the game server was lost, convert to a nn::Result object using qResult::GetNnResult(), and then pass that object to the error display function. The following message appears: Communication error has occurred.

If the same account is used to log in from another device, the original device is disconnected from the game server. When this happens, IsConnected() returns QERROR(RendezVous, ConnectionDisconnectedForConcurrentLogin) on the original device. If you pass this value to the error display function, a message appears stating that you have been disconnected from the server because you logged in from another device.


Return Values

"QSUCCESS(Core, Success)": Connecting to game server (online).

QERROR(RendezVous, ConnectionDisconnected): Offline.

QERROR(RendezVous, ConnectionDisconnectedForConcurrentLogin): Offline because another device logged in.

bool nn::nex::BackEndServices::Terminate ( CallContext *  pContext)

Terminates NgsFacade, and puts in a state where it can be deleted.

This function can be called while online, offline, logging in, or logging out, so termination of the asynchronous process and transition to offline status are guaranteed.

When the status is either logging in, logged in, or logging out, NgsFacade::Terminate is called by the NgsFacade destructor and blocks until the status transitions to offline. We recommend calling NgsFacade::Terminate before destroying NgsFacade.

Before calling this function, make sure that you run the Unbind() function of a class derived from ServiceClient (such as MatchmakeExtensionClient or NATTraversalClient) and perform the deletion process.

Asynchronous processing can take a long time when the local device is not connected to a network, so you can set the mode to forced termination mode using the Core::SetTerminateImmediately() function.

Parameters
[in,out]pContextCall information.


Return Values

true: Successfully started asynchronous processing.

false: Cannot start asynchronous processing because the status of the specified pContext is CallContext::CallInProgress. This value indicates that it is being used in other asynchronous processing. Because this is a programming error, it causes an assertion failure and halts execution on non-release builds.

bool nn::nex::BackEndServices::RegisterNotificationEventHandler ( NotificationEventHandler *  pNotificationEventHandler)

Registers a notification event handler.

Registers a notification event handler. Call this function to have the NotificationEventHandler::ProcessNotificationEvent callback invoked every time a notification event is received. To receive all notification events, call this function before NgsFacade::Login(). If you call this function after running NgsFacade::Login(), you may fail to receive notification events that were sent between those two function calls. You can register more than one event handler.

Parameters
[in]pNotificationEventHandlerPointer to the notification event handler to register.
Return Values

true: Success.

false: Attempted to register the same event handler more than once.
