Changes From NEX 3.x

This document provides an overview of the main changes from NEX 3.x in NEX 4.0.

Overall Changes to NEX

Migration Considerations

  • The internal character encoding was changed from UCS-2 (UTF-16 without surrogate pairs) to UTF-8. The qChar type used to be a typedef of wchar_t. qChar is now a typedef of char. wchar_t-type strings passed to the String class constructor are now converted from wide characters to UTF-8.

  • Changed the name of the _T macro that determines whether the L prefix (which indicates that a string is a wide character literal) is appended when strings are defined to NEX_T.

  • NEX_T("ABC") would substitute "ABC", not L"ABC".

  • The C99 standard integer types are now used for integer definitions. The following table shows the correspondence between the standard integer types and the proprietary defined types that start with a lowercase q in NEX3 and NEX4.

    Correspondence Between Basic Types Defined by NEX and the SDK
    NEX3 NEX4
    qBool bool
    qByte Same
    qInt8 int8_t
    qUnsignedInt8 uint8_t
    qInt16 int16_t
    qUnsignedInt16 uint16_t
    qInt32 int32_t
    qUnsignedInt32 uint32_t
    qInt64 int64_t
    qUnsignedInt64 uint64_t
    qInt int
    qUnsignedInt unsigned int
    qFloat Same
    qDouble Same
    qReal float
    qChar Same
    qChar8 char
    qChar16 char16_t
    qWideChar wchar_t
    qVector, qMap, and the like. Same

    The legacy qInt types are still defined to preserve compatibility and can be used as expected.

  • uint32_t, uint64_t, and the like, were used in places to represent data length and size, including for the return values of the String::GetLength() function. size_t is now used for data length and size. (In some cases, such as code related to communication formats, no changes were made.) Because size_t is defined as having a width of 64 bits in 64-bit computing, there may be a notification indicating that values have been truncated during compilation time if the size_t value is assigned something like uint32_t. If this happens, change the data type or cast to an appropriate type.

  • In accordance with this change, the signatures of the following callback functions have been changed. If you are overriding these callback functions on 64-bit architectures, you will have to use size_t for all such values. Non-pure virtual functions in particular may not work correctly if you do not use size_t everywhere (even though no compiler errors will occur).

    When you overload the DataStoreGetObjectEventListener::Begin() function, for example, when using LLVM/Clang to compile for 64-bit architectures, the MyDataStoreGetObjectEventListener::Begin hides overloaded virtual function [-Woverloaded-virtual] warning is displayed if you are not using size_t throughout.

    • DataStoreGetObjectEventListener::Begin()
    • DataStoreGetObjectEventListener::ProcessResponse()
    • DataStorePostObjectEventListener::PostChunkedBuffer()

  • In NX, principal IDs are uint64_t values rather than uint32_t values. Principal IDs are still uint32_t values on CTR and Wii U. This change was made so that principal IDs have the same type as network service account IDs. For more information about network service accounts, see the NX Account Guide. For more information about user management, see the User Management section of the programming manual.

  • The NX uses HTTPS for communication with the game server. HTTPS communication is carried out using libcurl.

    • Specify a thread-safe allocator regardless of the NEX thread mode when designating a proprietary memory allocator to libcurl. For more information, see libcurl Initialization [Required].

  • Although a proprietary zlib library was included in NEX, it was removed. Note that an error will occur when trying to link libosdk_zlib in the way it was originally linked.

Additions and Changes

  • Added support for the NX account feature. For more information, see User Management or Connecting to a Game Server.
  • Added support for the NX friend and block lists.
  • The String::GetLength() function returns the length of a string in bytes. Use the String::GetWideCharLength() function to get the length of a string in characters.
  • Added functions to set and get the thread priority used when connecting to the game server: RootTransport::SetConnectThreadPriority() and RootTransport::GetConnectThreadPriority(). Also added functions to set and get the CPU core that will run: RootTransport::SetConnectThreadCoreNo() and RootTransport::GetConnectThreadCoreNo().
  • Added functions to set and get internal thread priority: Core::SetInternalThreadPriority() and Core::GetInternalThreadPriority(). Also added functions to set and get the CPU core that will run: Core::SetInternalThreadCoreNo() and Core::GetInternalThreadCoreNo().
  • Previously, when the Scheduler::SetInternalThreadDispatchInterval() function was used, internal threads would go to sleep for the specified amount of time after calling the Scheduler::Dispatch() function. Now, the Scheduler::Dispatch() function is called again, after the specified amount of time elapses after the previous call to Scheduler::Dispatch(). That is, the amount of the next sleep time is reduced accordingly when the Scheduler::Dispatch() function takes an extended amount of time to run.

Messaging

Additions and Changes

  • Deprecated the UserMessage::GetRecipientID() function. Use the UserMessage::GetRecipientPrincipalID() or UserMessage::GetRecipientGatheringID() function instead.

Matchmaking

Additions and Changes

  • Changed the type of the values that can be determined by the NotificationEvent::GetParam1(), NotificationEvent::GetParam2(), and NotificationEvent::GetParam3() functions from uint32_t to uint64_t. As a result, the NotificationEvent::GetUInt64Param1() function is deprecated. You can now use the NotificationEvent::GetParam1() function to get the same value. To maintain backward compatibility, you can continue to use the NotificationEvent::GetUInt64Param1() function when migrating from NEX 3.x. In addition, the NotificationEvent::GetParam1() function now gets the NotificationEvents::RoundStarted, NotificationEvents::FirstRoundReportReceived, and NotificationEvents::RoundSummarized states instead of the NotificationEvent::GetUInt64Param1() function.
  • You can now specify negative values for the score parameter in the score conversion settings for the scored auto-matchmaking feature. For more information, see Setting Score Conversion Settings.
  • You can use the score conversion settings for the scored auto-matchmaking feature to specify threshold values used when selecting a matchmaking session to join from a list of candidates. For more information, see Setting Score Conversion Settings.
  • Deprecated the MatchmakeExtensionClient::GetPlayingSession() function and added the MatchmakeExtensionClient::FindMatchmakeSessionByParticipant() function as a replacement.
  • Added the MatchmakeExtensionClient::FindMatchmakeSessionByGatheringId() function to enable searching for a MatchmakeSession using the specified GatheringID.
  • Added the MatchmakeExtensionClient::FindMatchmakeSessionByOwner() function to enable searching for a MatchmakeSession using the specified owner principal ID.
  • The MatchmakeExtensionClient::UpdatePrivacySetting() function is now private.
  • Blacklists are now called block lists.
  • Added the MatchmakeBlockListParam parameter class, which specifies whether to ignore the block list settings. This class can be used with the version of the MatchmakeExtensionClient::AutoMatchmake() function that takes AutoMatchmakeParam as a parameter, and with the versions of the MatchmakeExtensionClient::JoinMatchmakeSession() and MatchmakeExtensionClient::FindMatchmakeSessionByParticipant() functions that take JoinMatchmakeSessionParam as a parameter.
  • The friend matchmaking functionality that specifies MATCHMAKE_SYSTEM_TYPE_FRIEND will be removed. To replace this functionality, instead use the device's friend presence functionality to get a list of friends currently online, and then use MatchmakeExtensionClient::FindMatchmakeSessionByParticipant() to get a list of joinable matchmaking sessions.
