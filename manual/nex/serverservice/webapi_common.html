11.1. Using WebAPI

This section describes how to use WebAPI and things to note when using it.

11.1.1. Purpose of WebAPI

WebAPI in NEX can be used for data management on the game server. WebAPI can be used for operations such as tabulating data and periodically posting and deleting data. WebAPI cannot be used for purposes such as executing client requests and frequent updating, because it is made available for management purposes instead.

See the NEX Guide for other important information.

11.1.2. Accessing WebAPI

To use WebAPI, you must apply to use a web service on OMAS. After your application is approved, you will be able to generate the OAuth 2.0 access token required to use WebAPI. For detailed procedures, see the OMAS Manual and the NDID Auth Server Manual.

11.1.3. Resource URL Path

The resource URL path of the API is generally structured as follows.

/nex/{moduleName}/v{version}/{apiPath}
Element Description
moduleName Module name
version API version
apiPath Path of function

For example, to search using version 2 of the data store API, you would use the following path.

/nex/datastore/v2/search

However, you do not specify the version in certain functions, such as those used for getting the version.

/nex/datastore/version

11.1.4. Request

11.1.4.1. Request Method

The request method is either GET, POST, PUT, or DELETE. The method to use depends on the function, as do the ways request parameters are passed and formatted.

11.1.4.2. Parameters and Request Body

To pass the parameters, in general, use the query string with the GET method and use the request body in an XML format with the POST and PUT methods. When making a request using the XML format, set the header to Content-type: text/xml. Parameters are not used with DELETE.

Request Example:

  • Get the metadata, including tags, for data ID 10 in the data store (GET).

    GET /nex/datastore/v2/metainfo/10?response=tag HTTP/1.1

  • Change the name of data ID 10 to "new name" in the data store (PUT).

    PUT /nex/datastore/v2/metainfo/10 HTTP/1.1

<change>
  <name>new name</name>
</change>

11.1.4.2.1. Multiple Values

Some of the functions accept multiple values. You generally use commas to delimit multiple values when using GET, and use multiple XML elements when using POST and PUT.

Request Example:

  • Get the metadata for data IDs 10, 20, and 30 in the data store.

    GET /nex/datastore/v2/metainfo?data_ids=10,20,30 HTTP/1.1

  • Change the tags of data ID 10 to "tag1" and "tag2" in the data store (PUT).

    PUT /nex/datastore/v2/metainfo/10 HTTP/1.1

<change>
  <tags>
    <tag>dGFnMQ==</tag>
    <tag>dGFnMg==</tag>
  </tags>
  <param>
    <data_id>10</data_id>
  </param>
</change>

11.1.5. Response

11.1.5.1. Status Code

The execution result of a request generally uses one of the following status codes.

Status Code Description
200 Function completed successfully.
400 Invalid request parameter.
404 Path does not exist.
500 An internal error or the access token contains invalid characters.
502 Access token is invalid.

11.1.5.2. Content

Detailed execution results and content are returned in XML format. When the function succeeds, the content is as follows.

<? xml version="1.0" encoding="UTF-8"? >
<nex>
  <module>
    <! <!-- Response content -->
  </module>
</nex>

The <module> element above represents the module name. For example, the data store module would appear as follows.

<? xml version="1.0" encoding="UTF-8"? >
<nex>
  <datastore>
    <! <!-- Response content -->
  </datastore>
</nex>

If an error occurs, the following content is returned.

<? xml version="1.0" encoding="UTF-8"? >
<nex>
  <errors>
    <error>
      <errorcode><!-- Error code --></errorcode>
      <message><!-- Error message --></message>
    </error>
  </errors>
</nex>

11.1.6. Handling Special Request and Response Data

Some functions require the data to be processed before it is passed as an argument. The resulting data is also returned in the processed format.

11.1.6.1. Base64 Encoding

When using Base64 encoding, use RFC 3548-based encoding. The encoded data must also be in a URL-safe format.

Note the following points when encoding in Base64.

  • Use "=" for padding (when required).
  • Do not use newline characters.

The rules for making data URL-safe are as follows.

  • Use "-" instead of "+"
  • Use "_" instead of "/"

Conversion Examples:

  • Encode "NEX WebAPI"
    • NG: TkVYIFdlYkFQSQ (No padding)
    • OK: TkVYIFdlYkFQSQ==
  • Encode a byte array containing 0x3c, 0x3d, 0x3e, and 0x3f.
    • NG: PD0+Pw (Not URL safe and no padding)
    • NG: PD0+Pw== (Not URL safe)
    • NG: PD0-Pw (No padding)
    • OK: PD0-Pw==

11.1.7. Requests via WebAPI Gateway

To use WebAPI, you must access the game server through WebAPI gateway. Use the following URL to send a request to the game server through WebAPI gateway.

https://{Environment}api.nex.mng.nintendo.net/v4_0/{GameServerId}/{ResourceURLPath}
Element Description
Environment Specifies the development environment or the production environment. Specify dd1 for the development environment and lp1 for the production environment.
GameServerID Specifies the game server ID to be displayed in OMAS. The leading "0x" is not needed.
ResourceURLPath See 11.1.3. Resource URL Path.

An access token is required to issue a request. For more information about getting and updating access tokens, see the NDID Auth Server Manual.

Note:

When using access tokens, do not use the access tokens obtained by users who are developers. Instead create an account for that specific game title, and use the access tokens obtained for that account. Access tokens inherit the privileges of the user that issues them. If the user who issued the token loses those privileges due to retirement, transfer, or another reason, the access token becomes invalid.

11.1.7.1. Sample Request via WebAPI Gateway

This is a sample of a request for WebAPI through WebAPI gateway under the following conditions.

Element Description
GameServerID 0x1234abcd
Environment dd1
Access Token abcd123456
Function Get metadata for data ID 123456.

To make a request with these conditions, execute the following request.

GET https://dd1api.nex.mng.nintendo.net/v4_0/1234abcd/nex/datastore/v2/metainfo/123456
Authorization: OAuth abcd123456

To do this with cURL, use the following command.

curl -H "Authorization: OAuth abcd123456" --proxy http://<proxy_address>:<proxy_port> https://dd1api.nex.mng.nintendo.net/v4_0/1234abcd/nex/datastore/v2/metainfo/123456
