11.4. DataStore

11.4.1. General Information

Module name datastore
API version 2

The following values must be encoded in Base64 in the request. The response also uses Base64 encoding.

  • Meta-binary data
  • Tags

11.4.2.2. Changing Metadata

Changes the metadata of data.

Although generally only the specified information is changed, the expiration is also updated if the number of days valid or date modified is changed.

PUT /nex/datastore/v2/metainfo/(data_id)

Changes the metadata for one piece of data, data_id.

Parameters:

Name Description
data_id The data ID to change. Required.

Request Body:

Element Parent Elements Description
change   Root element. Required.
name change Name.
type change Data type
period change The number of valid days.
status change The status. For more information, see the following table.
access_permission change Access permission. Configured in the child element.
update_permission change Update permissions. Configured in the child element.
type access_permission, update_permission Permission type. For more information, see the following table.
recipient_ids access_permission, update_permission User with permission. If type is specified or specified_friend, specify in the recipient_id child element.
recipient_id recipient_ids User with permission. More than one can be specified.
tags change Returns tags. Specify in the tag child element.
tag tags Tags. Specify the value as a URL-safe Base64-encoded string. Multiple values can be specified (up to 16).
meta_binary change Meta-binary data. Specify the value as a URL-safe Base64-encoded string.
modify_updated_time change To update the modified date to the current date, specify 1.

status

Value Description
none Normal state.
pending Rating Pending
rejected Rejected.

access_permission/type, update_permission/type

Value Description
public Overall.
friend Friends only.
specified Only the specified recipients. Must be specified in the recipient_ids element.

11.4.2.5. Uploading Data

11.4.2.5.1. Upload Procedure

11.4.2.5.1.1. Ordinary Data
  1. Prepare to upload using prepare. Set size to the size of the data to upload (in bytes). Specify other parameters as necessary.
  2. On success, the location where the data was uploaded and other information is returned. You can upload data to a storage server based on this information. (You must use multipart form-data.)
  3. If the upload completes successfully, call complete and include the data ID returned from prepare in the path.
  4. If 200 is returned, the function succeeded.
11.4.2.5.1.2. Meta-Binary Only
  1. Prepare to upload using prepare. The size parameter is 0. Set flag to not_use_storageserver, and the data to upload to meta_binary as a URL-safe Base64-encoded string.
  2. If the same XML as usual is returned, the operation was successful. Only the data ID is specified.
  3. You do not need to call complete.

Example command when uploading data to the storage server:

When using cURL to upload data to the storage server, issue a request as in the following example.

curl \
  --request POST \
  --header "date: Wed, 01 Jan 2013 00:00:00 GMT" \
  --form x-amz-algorithm=AWS4-HMAC-SHA256 \
  --form x-amz-credential=XXXX \
  --form x-amz-date=20130101T000000Z \
  --form x-amz-signature=XXXX \
  --form key=XXXX \
  --form acl=private \
  --form policy=XXXX \
  --form "file=@C:/path/to/upload_file.bin" \
  https://dev.example.org/

Note:

  • Content-Type must be multipart/form-data. If uploading to the storage server with the POST method fails, verify that the request header includes Content-Type: multipart/form-data; boundary=.
  • Specify the data to upload using the file parameter. The file parameter must be the last request parameter (the last field in the form).

11.4.2.6. Getting the URL

GET /nex/datastore/v2/urlinfo/(data_id)

Gets the URL for a single piece of data, data_id.

This URL contains authentication information, so it can be used to download data from the storage server.

Use this URL within minutes after getting it. The reason is because the specifications for the storage server might be changed in the future in a way that makes it impossible to honor the number of days of validity specified for the URL.

Parameters:

Name Description
data_id The data ID to get the URL for. Required.
period The number of days that the URL is valid. The default is 7. The maximum value is 7.
