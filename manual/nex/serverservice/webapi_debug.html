11.6. WebAPI Debug Assistance

11.6.1. General Information

Module name debug
API version 2

11.6.2. Error Simulation

The function names included in WebAPI parameters and responses for error simulation are the names as used in the game server, and these names differ from the function names called from the application. For more information about the correspondence with the function names as called from the application, see 9.5. Function Name Correspondence Tables.

Note: Calling functions from the application has been deprecated.

11.6.2.1. Getting Registered Error Simulation Settings

This process gets the registered error simulation settings.

When error simulation settings expire, they are deleted from the game server and are not included in the result of WebAPI.

GET /nex/debug/v2/simulations/(principal_id)/(rmc_name)

This request gets the error simulation settings that have been registered for the specified principal ID and API function.

Parameters:

Name Description
principal_id Principal ID. Required.
rmc_name Server API function name. Required.

Request Example:

GET /nex/debug/v2/simulations/1001/DataStoreProtocol%3A%3ASearchObject HTTP/1.1

Response Body:

Element Parent Elements Description
simulations   Root element.
simulation simulations The error simulation settings.
rmc_name simulation Server API function name.
count simulation The number of remaining times to apply the error simulation settings.
exec_order simulation The order in which to apply the error simulation settings. If more than one set of error simulation settings have been registered for the same API function, they are applied in order from the smallest.
return_code simulation Return code.
facility simulation The facility.
error_code simulation The name of the error code.
network_error_code simulation Network error code.

Response Example:

HTTP/1.1 200 OK
Content-Type:  text/xml;charset=utf-8

<? xml version="1.0" encoding="UTF-8"? >
<nex>
  <debug>
    <simulations length="2">
      <simulation>
        <rmc_name>DataStoreProtocol::SearchObject</rmc_name>
        <count>1</count>
        <exec_order>0</exec_order>
        <return_code>2154364932</return_code>
        <facility>DataStore</facility>
        <error_code>NotFound</error_code>
        <network_error_code>1204</network_error_code>
      </simulation>
      <simulation>
        <rmc_name>DataStoreProtocol::SearchObject</rmc_name>
        <count>2</count>
        <exec_order>1</exec_order>
        <return_code>2154364930</return_code>
        <facility>DataStore</facility>
        <error_code>InvalidArgument</error_code>
        <network_error_code>1202</network_error_code>
      </simulation>
    </simulations>
  </debug>
</nex>

11.6.2.3. Registering Error Simulation Settings

This process registers error simulation settings.

PUT /nex/debug/v2/simulations
POST /nex/debug/v2/simulations/put

Request Body:

Element Parent Elements Description
change   Root element. Required.
principal_id change The principal ID. Required.
rmc_name change Server API function name. Required.
timeout change The validity period (in seconds) of the error simulation settings. The default value is one hour.
param change The parent element for the content of the simulation settings to register. More than one can be specified. Required.
return_code param Return code.
facility param The facility. If facility is specified, you must specify either success_code or error_code.
success_code param The name for the success code. (Example: "Success")
error_code param The name for the error code. (Example: "InvalidArgument")
network_error_code param Network error code.
count param The number of times to apply the error simulation settings. Configured in the child element. Required.

By specifying more than one param value, you can change the error that is returned to the client depending on how many times the API function has been called.

You can specify any one of return_code, facility, and network_error_code. For the available information that can be obtained, see 11.6.2.7. Getting Result Information.

If neither return_code, facility, nor network_error_code has been specified, the API executes normally. Say you want the DataStoreClient::SearchObject() function to return the error QERROR(DataStore, InvalidArgument) the first time it is called, to execute normally the second time, and to return the error QERROR(DataStore, Unknown) the third time. To realize this sequence where normal execution is sandwiched between errors, do not specify any error for that second call when you register the error simulation settings.

Request Example:

In the following example settings, errors are returned as registered in the error simulation settings by the system with the principal ID 1001 when it calls the DataStoreClient::SearchObject() function (the name of the function within the library is DataStoreProtocol::SearchObject() ).

  • 1st Call: Returns an error with a return code of 2154364932 (corresponding to QERROR(DataStore, NotFound)).
  • 2nd Call: Returns the error QERROR(DataStore, Unknown).
  • 3rd Call: Returns an error with a network error code of 006-1201 (corresponding to QERROR(DataStore, Unknown)).
  • 4th Call: Returns an error with a network error code of 006-1202 (corresponding to QERROR(DataStore, InvalidArgument)).
PUT /nex/debug/v2/simulations/ HTTP/1.1

<change>
  <principal_id>1001</principal_id>
  <rmc_name>DataStoreProtocol::SearchObject</rmc_name>
  <param>
    <count>1</count>
    <return_code>2154364932</return_code>
  </param>
  <param>
    <count>1</count>
    <facility>DataStore</facility>
    <error_code>Unknown</error_code>
  </param>
  <param>
    <count>1</count>
    <network_error_code>006-1201</network_error_code>
  </param>
  <param>
    <count>1</count>
    <network_error_code>61202</network_error_code>
  </param>
</change>

Response Example:

HTTP/1.1 200 OK
Content-Type:  text/xml;charset=utf-8

<nex>
  <debug>
    <simulations>
      <changed length="4"/>
    </simulations>
  </debug>
</nex>

length is the number of error simulation settings that have been registered.

11.6.2.4. Deleting Error Simulation Settings

This process deletes the registered error simulation settings.

POST /nex/debug/v2/simulations/delete

Request Body:

Element Parent Elements Description
delete   Root element. Required.
principal_id delete The principal ID. Required.
rmc_name delete Server API function name.

If both a principal ID and an API function name have been specified, only the simulation settings registered to that ID and that name are deleted.

If only a principal ID has been specified, all simulation settings registered to that ID are deleted.

Request Example:

POST /nex/debug/v2/simulations/delete HTTP/1.1

<delete>
  <principal_id>1001</principal_id>
  <rmc_name>DataStoreProtocol::SearchObject</rmc_name>
</delete>

Response Example:

HTTP/1.1 200 OK

11.6.2.5. Getting Error Simulation Execution Logs

This process gets the logs of executions of the error simulation settings.

When an execution log has expired, it is deleted from the game server and is not included in the result of WebAPI.

GET /nex/debug/v2/simulation_logs/(principal_id)

This request gets the execution logs for the error simulation settings applied to the specified principal ID.

Parameters:

Name Description
principal_id Principal ID. Required.

Request Example:

GET /nex/debug/v2/simulation_logs/1001 HTTP/1.1

Response Body:

Element Parent Elements Description
simulation_logs   Root element.
simulation_log simulation_logs The execution logs of the error simulation settings.
rmc_name simulation_log Server API function name.
return_code simulation_log The return code returned to the client.
datetime simulation_log The date and time when the error simulation settings were applied.
facility simulation_log The facility.
error_code simulation_log The name of the error code.
network_error_code simulation_log Network error code.

Response Example:

HTTP/1.1 200 OK
Content-Type:  text/xml;charset=utf-8

 <? xml version="1.0" encoding="UTF-8"? >
 <nex>

     <simulation_logs length="2">

11.6.2.7. Getting Result Information

This process gets information about the result returned by the NEX API. This process includes the following result information.

  • The facility
  • Success code name and error code name
  • Return code
  • The last four digits of the network error code

The following errors are not included in the result of WebAPI.

  • Errors returned by SystemError
GET /nex/debug/v2/result_codes

This process gets information about the result returned by the NEX API.

Request Example:

GET /nex/debug/v2/result_codes HTTP/1.1

Response Body:

Element Parent Elements Description
result_codes   Root element.
result_code result_codes Information about the result.
network_error_code result_code Network error code.
return_code result_code Return code.
facility result_code The facility.
success_code result_code The name of the success code.
error_code result_code The name of the error code.

Response Example:

HTTP/1.1 200 OK
