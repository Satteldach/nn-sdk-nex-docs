3. Managing Connections

3.1. Connecting to a Game Server

There are two methods for logging in for the current version.

  • Log in to a game server that was specified in advance, using a designated user name and password.
  • Log in by specifying the game server ID, the access key, and the network service account information.

If you intend to log in by specifying the game server ID, the access key, and the network service account information, prepare in advance as described in Account Library / Using Network-Service Accounts in NintendoSDK Documents.

You can either use NgsFacade::GetLastLoginNnResult to get the nn::Result value or NgsFacade::GetLastLoginErrorCodeStruct() to get the error code when the NgsFacade::Login asynchronous processing fails.

For sample code, see the NnSdkLogin sample and the account library sample demo included in NexDemoUtil.

The server version is checked during login, and a QERROR(Authentication, ServerVersionIsOld) is generated if it is earlier than the version expected by the client library. This problem sometimes happens in the development environment, depending on the OMAS request and approval status, but will be resolved within a few days. Contact Nintendo if this condition continues for a long time.

Note:

You cannot log in to the same game server at the same time from multiple different devices when those devices are associated with the same Nintendo Account. An attempt to log in to a game server from a separate device associated with the same Nintendo Account as for a device already logged in to the game server will succeed, but the device that logged in first will be automatically logged out.

3.2. Disconnecting From the Game Server

Use the NgsFacade::Logout() function to disconnect from a game server. This function takes a pointer to a ProtocolCallContext class object as an argument. If a client logs out while it is still in a matchmaking session, the game server automatically removes that user from the matchmaking session.

The NEX library transmits a keep-alive to the game server that it is logged in to when there are no explicit requests from the client. If communication with the game server is not possible for 30 seconds or longer because the connection with the access point was lost, the system was turned off, or for another reason, the game server concludes that the client has logged out and automatically changes the user's status to offline.

Note:

When attempting to free an NgsFacade class object when the status is logging in, logged in, or logging out, NgsFacade::Terminate() is called by the NgsFacade destructor and blocks until the status transitions to offline. We recommend calling the NgsFacade::Terminate() function before destroying the NgsFacade class object.
