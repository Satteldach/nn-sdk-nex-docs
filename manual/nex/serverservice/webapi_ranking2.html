11.3. Ranking2

11.3.1. General Information

Module name ranking2
API version 1

11.3.2. Settings API

Use this API to get and modify the settings in Ranking2. For more information about each feature, see 6.9. Settings.

11.3.2.1. Getting Category Type Settings

These methods get category type settings.

If you specify a category type that has not yet been configured, the default settings are retrieved. When getting the settings for all category types, the settings for unconfigured category types are not retrieved. Only the settings for configured category types are retrieved. If no categories have been configured, 0 categories are included in the response.

For more information about which values can be retrieved, see 6.9.2. Category Type Settings.

GET /nex/ranking2/v1/category_type_settings/(category_type_id)

Gets the settings for a single category type.

Parameters:

Name Description
category_type_id The number of the category type for which to retrieve season data. Only one can be specified.

Request Example:

GET /nex/ranking2/v1/category_type_settings/1 HTTP/1.1

11.3.2.2. Changing Category Type Settings

These methods change category type settings.

For more information about which values can be configured, see 6.9.2. Category Type Settings.

PUT /nex/ranking2/v1/category_type_settings
POST /nex/ranking2/v1/category_type_settings/put

Changes the settings for multiple category types. Settings for which a new value is not specified are not changed.

Request Body:

Element Parent Elements Description
change   Root element. Required.
category_type_settings change Required.
category_type_setting category_type_settings Use multiple instances of this element to change the settings for multiple category types. Required.
category_type category_type_setting Category type number. Required.
min_score category_type_setting Minimum valid score. 0 to 4,294,967,295, and no greater than max_score. Must be specified at the same time as max_score.
max_score category_type_setting Maximum valid score. 0 to 4,294,967,295, and at least min_score. Must be specified at the same time as min_score.
score_order category_type_setting Score order. 0: Ascending, 1: Descending
lowest_rank category_type_setting The last place in rankings. 1 to 10000.
max_seasons_to_go_back category_type_setting The number of past seasons to save. 0 to 100.
reset_mode category_type_setting The periodic reset mode.
reset_hour category_type_setting The time of day at which to reset rankings. 0 to 23. UTC.
reset_day category_type_setting The day on which to reset rankings. 1 to 28 (for days of the month) or 0 to 6 (for days of the week). UTC.
reset_month category_type_setting The months in which to reset rankings. 1 to 4095 (A 12-bit value, where each bit represents one month. The lowest bit is January, the next bit is February, and so on.) UTC.

When periodic reset settings are modified, the time at which to start the next season must be recalculated. To do this, initialize the season data or change the season data to the desired season number and period of time. Also, delete the score data and delete all scores remaining in the category (the season 0 scores).

The value of the periodic reset setting may be copied across server environments. For this reason, this operation must be performed not only in the server environment where the periodic reset setting was changed (such as the development environment), but also server environments where it was copied to (such as the production environment).

11.3.3.2. Modifying Season Data

These methods modify season data.

If you change the season numbers, retrieving and resetting season data should be performed using the new season numbers, and the data for the older seasons will be deleted. Be careful when changing season numbers because erroneous score data may be retrieved if left remaining in the older seasons.

Changing season_to to a future date ensures that the season number will not be changed until the specified date/time, regardless of the applicable periodic reset settings. For example, this can be useful if you want a ranking category to be reset daily but you want the season number to remain at 0 during the server configuration/game testing period before the official game launch.

PUT /nex/ranking2/v1/season_info_entries
POST /nex/ranking2/v1/season_info_entries/put

Modifies the season data for the category types specified in the request body.

Request Body:

Element Parent Elements Description

season_info_entry season_info_entries Use multiple instances of this element to change the season data for multiple category types. Required.
category_type season_info_entry Category type number. Required.
season season_info_entry Season number. 0 to 2147483647. Required.
season_from season_info_entry The date/time at which the current season started. The format is %Y-%m-%dT%H:%M:%SZ. UTC. Required.
season_to season_info_entry The date/time at which the current season will end. The format is %Y-%m-%dT%H:%M:%SZ. UTC. Required.

11.3.3.3. Force-Incrementing the Season Number

These methods advance the season number by one. Use these methods if you need to force-increment the season number during testing/debugging.

These methods only change the season number. The season start date/end date does not change. To change the start/end date, see Modifying Season Data.

When the season number is advanced, the data for older seasons (seasons older than the configured number of seasons for which to save data) becomes scheduled for deletion but is not deleted immediately. Old season data is deleted as part of the next periodic reset process.

These methods will not change the season number of category types that are not configured to be periodically reset.

PUT /nex/ranking2/v1/season_info_entries/setting_forward
POST /nex/ranking2/v1/season_info_entries/setting_forward/put

Advances the season number of the category types specified in the request body.

category_type season_info_entry The number of the category type for which to advance the season. Required.

Request Example:

PUT /nex/ranking2/v1/season_info_entries/setting_forward HTTP/1.1

<change>
  <season_info_entries>
    <season_info_entry>
      <category_type>0</category_type>
    </season_info_entry>
    <season_info_entry>
      <category_type>1</category_type>
    </season_info_entry>

11.3.4. Ranking API

Use this API to get, upload, or delete rankings or individual scores.

11.3.4.1. Getting Rankings

Gets rankings. This method can only get rankings in range ranking mode. For more information about range ranking mode, see 6.6.1. Ranking Types.

Gets the rankings for the specified category using the specified parameters.

11.3.9. Population API

Use this API to populate ranking categories/category types with test data for debugging purposes.

11.3.9.1. Data Population

These methods allow you to populate ranking categories/category types with scores and common user data. This feature is intended for use in application debugging. Specify a category and a range of scores to populate the category with data.

If called when scores have already been added, existing scores are overwritten and updated.

For each user, data is uploaded to every category from min_category to max_category. However, you cannot specify a range of greater than 10,000 categories. Specifying a category_id results in population of only that category.

The score values and miscellaneous data are generated randomly within the specified range of values. The principal ID is used to generate a name for the associated common user data. For example, if the principal ID is 18354450593889115336, PID=feb81b91b037dcc8 in lowercase hexadecimal. For the binary data of the common user data, a random string of the specified length is generated.

If uploaded, invalid scores will not be isolated from the regular scores and are saved in the same location as the regular scores.

Also, scores lower than the last place score are always uploaded during the data population process. These scores are deleted as part of a periodic deletion process.

PUT /nex/ranking2/v1/scores/population
POST /nex/ranking2/v1/scores/population/put
PUT /nex/ranking2/v1/categories/(category_id)/scores/population
POST /nex/ranking2/v1/categories/(category_id)/scores/population/put

Uploads data according to the specified parameters.

Parameters:

Name Description
category_id The category number of the category to which to upload data.

Request Body:

Element Parent Elements Description
populate   Root element. Required.
param populate Required.
num param The number of dummy users for which to upload data (per category). Maximum value is 20,000. Required.
min_category param The minimum category number of a category to which to upload data. 0 if unspecified. Cannot be used in combination with category_id.
max_category param The maximum category number of a category to which to upload data. 0 if unspecified. Cannot be used in combination with category_id.
min_score param The minimum score to upload. If unspecified, the default value is 0.
max_score param The maximum score to upload. If unspecified, the default value is 4294967295.
min_misc param Minimum miscellaneous data to register. If unspecified, the default value is 0.
max_misc param Maximum miscellaneous data to register. If unspecified, the default value is 0xFFFFFFFFFFFFFFFF.
common_data_binary_size param The size to use when uploading the binary data portion of common user data. If unspecified, the default value is Ranking2Constants::MAX_BINARY_DATA_LENGTH.
dist_name param Random number distribution name. uniform (uniform distribution), normal (normal distribution), lognormal (logarithmic normal distribution). uniform if unspecified.
dist_param1 param Parameter number 1. If normal, the mean (numerical mean) at mu. If lognormal, the median (median value).
dist_param2 param Parameter number 2. If normal, the standard deviation at sigma. If lognormal, the sigma.

Request Example:

PUT /nex/ranking2/v1/scores/population HTTP/1.1

<populate>
  <param>
    <num>100</num>
  </param>
</populate>

Response Example:

HTTP/1.1 200 OK
Content-Type:  text/xml;charset=utf-8

<? xml version="1.0" encoding="UTF-8"? >
<nex>
  <ranking2>
    <scores>
      <populated length="100"/>
    </scores>
  </ranking2>
</nex>

length is the number of scores that were uploaded.

Random number distribution:

When dist_name is uniform

  • Generates a uniform distribution of random numbers from min_score to max_score.
  • dist_param1 and dist_param2 are ignored.

When dist_name is normal

  • Generates a normal distribution of random numbers, appropriate for a normal descending sequence of scores.
  • The probability density function is defined as f(x) = 1 / (sqrt(2 × pi) × sigma) × exp( –((x – mu)² / (2 × sigma²))).
  • dist_param1 is the mean of random numbers corresponding to mu. If dist_param1 is omitted, this is 3 × min_score / 4 + max_score / 4.
  • dist_param2 is the standard deviation of random numbers corresponding to sigma. If dist_param2 is omitted, this is (max_score – min_score) / 8.
  • The random numbers are regenerated if they exceed min_score or max_score.

When dist_name is lognormal

  • Generates a logarithmic normal distribution of random numbers, appropriate for an ascending sequence of scores, such as for Time Attack.
  • The probability density function for a logarithmic normal distribution is normally defined as f(x) = 1 / (sqrt(2 × pi) × sigma) × x) × exp( –((log x – mu)² / (2 × sigma²))). However, when shifted by the min_score, it is defined as f(x) = 1 / (sqrt(2 × pi) × sigma × (x – min_score)) × exp( –((log (x – min_score) – mu)² / (2 × sigma²))).
  • dist_param1 is the mean of random numbers, and corresponds to mu = log (dist_param1 – min_score). If dist_param1 is omitted, this is 3 × min_score / 4 + max_score / 4.
  • dist_param2 corresponds to sigma, and is 0.5 when omitted.
  • The random numbers are regenerated if they exceed max_score. min_score is not generated based on the characteristics of the random numbers.

You can use Ranking2PopulationDistribution.xlsx to check the probability distribution when dist_name is normal or lognormal.
