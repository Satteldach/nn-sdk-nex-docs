Version 4.6.7 (2022-03-18)

Additions and Changes

General

  • When building applications on Windows, it is no longer possible to replace vsnprintf() with _vsnprintf() in the same way that can be done with snprintf() and _snprintf_s().
  • Memory is no longer allocated dynamically by String::FindSubstringCase() and String::FindSubstringNoCase().

Sample Demos

  • When an instance of nn::Result is created, {} is specified to explicitly initialize the object.

Bug Fixes

General

  • When logging in to the game server, sometimes memory was dynamically allocated unintentionally. This bug was fixed.
    • Due to this bug, there was a risk of the application crashing when a memory allocator that was not thread-safe was set in the NEX library.

DataStore

  • Fixed a bug in the overloads of the DataStoreChangeMetaCompareParam::SetMetaBinary(), DataStoreChangeMetaParam::SetMetaBinary(), and DataStorePreparePostParam::SetMetaBinary() functions that take qVector<qByte> as an argument. Due to this bug, there was a risk of an assertion failure occurring in the application if it was built in Windows and a qVector of size 0 was specified for the argument.

Revisions to Documentation

General

  • In Sample Demo List, noted that the Nintendo Switch Online policy for the application ID specified in the sample demos is No features require membership.
  • Added a description of the DELETE method to a number of the features in the DataStore, Matchmaking, and Debug Assistance sections of the WebAPI documentation. Previously, this was unintentionally made private.
  • In Common Errors, corrected a typo in QERROR(RendezVous, GameServerMaintenance).
  • The following functions are now private. Previously, they were unintentionally made public. These functions cannot be used in NX NEX.
    • The GetOutputEmulationDevice() member function of the RootTransport class
    • The EmulationDevice class and its derived classes (InputEmulationDevice and OutputEmulationDevice)

Matchmaking

  • In the search criteria for matchmaking sessions (MatchmakeSessionSearchCriteria), the default value for the VacantOnly element is now set to true. This change was included in NX NEX 4.0.0, but its addition was omitted from the API Reference.
  • The Set(), Get(), and Remove() member functions of the StationURL class have been deleted from the API Reference.
    • Their use is prohibited in new applications (including patches) for master ROM submission.
    • If you use these functions, there is a risk that future server updates will lead to communication failures by API resources that take StationURL as an argument.

DataStore

  • In Data Status, added information about the ways in which the status can transition when the status of data in the data store is manipulated on NMAS (NMAS2).
  • In DataStore, noted that the data URLs obtained using WebAPI contain authentication information for downloading the data.

Debug Assistance

  • In the Introduction, noted that the features to assist in debugging will no longer be available from the application in the future.

Version 4.2.0 (2017-06-09)

Additions and Changes

General

  • Made VSocket public. Using VSocket enables peer-to-peer-to-peer communication between clients on any third-party network engine while using NEX server features, the NAT traversal feature, and encryption and modification detection features. An online battle system that uses VSocket and NEX matchmaking was implemented with Unreal Engine 4. For more information, contact Nintendo.
  • A timeout period could previously be specified as the third parameter of VSocket::ProbeStations(), but now the timeout value is automatically set internally, and the specified value is ignored. In addition, the timeout result was previously QERROR(Core, Timeout), but has been changed to QERROR(Transport, NatTraversalError).
  • Added the Initialize() and Finalize() functions. Use this function to control when to initialize the Core object. This prevents the problem where the object is initialized at an unintended time when settings such as the thread mode are not correctly configured. Calling Initialize() and Finalize() is not required.
  • Calling GlobalVariables::AcquireInstance() and GlobalVariables::ReleaseInstance() is no longer required. There is no issue calling these functions in the same way as they were previously called.
  • When there is a disconnect from the game server, previously QERROR(Transport, ConnectionFailure) would be obtained as the asynchronous processing results returned from NgsFacade::IsConnected(), but now QERROR(RendezVous, ConnectionDisconnected) is returned.
  • If a user is disconnected from the game server because another user with the same principal ID has logged in, the NgsFacade::IsConnected() previously returned QERROR(Transport, ConnectionFailure) as a result of asynchronous processing. QERROR(RendezVous, ConnectionDisconnectedForConcurrentLogin) is now returned instead.
  • The NgsFacade::EnableLoginDataCache() function is now private. It can be used because it is compatible with existing codes, but it has no particular effect even if it used.
  • Previously, the specification did not allow you to use CallContext::GetOutcome() to get a result if CallContext::Cancel() was called and the state became CallContext::CallCancelled(). It has been changed so that the results can be obtained as QERROR(Core, Cancelled).
  • Added CallContext::RegisterCompletionCallbackGeneric() to CallContext and its subclasses. Use it to specify any function pointers, function objects, and lambda expressions that take CallContext as an argument. You can also specify a function that does not take parameters by using AddCallContextArgumentAdapter().
  • Most RMC asynchronous processing functions would return false if they were called while disconnected from the server. These functions were changed so that asynchronous processing begins even in that situation, and they now return true. This change means that an asynchronous processing function will only return false if the CallContext object currently in use is specified. However, follow the description in the API Reference if the asynchronous processing function does not return bool, or has a special note.
  • In some cases, with callbacks from within the function before returning from the function, CallContext::RegisterCompletionCallback() was used to set the callback function, and RMC asynchronous processing was called. (These cases include those where an RMC was called while disconnected from the server.) The specifications have been changed so that the system calls back from Scheduler::Dispatch(), instead of calling back from within the function.
  • Previously, the Scheduler::Dispatch(), Scheduler::DispatchAll(), and CallContext::Wait() functions could not be called in parallel from multiple threads, but now you can call these functions when in thread-safe mode. (Multiple CallContext::Wait() functions or Scheduler::Dispatch() functions can also be called in parallel. The functions will not block each other when they are called.) Along with this change, the Scheduler::Dispatch() function, which previously returned the number of remaining jobs that can be executed, will always return 0.
  • Added CallContext::WaitWithoutDispatch(). Because this function does not call Scheduler::Dispatch() internally, Scheduler::Dispatch() can be called in parallel, even when you are not in thread-safe mode.
  • Added Scheduler::GetReadyJobsSize(). This function returns the current number of executable jobs.
  • Added ThreadedJob. This function enables you to execute optional processing asynchronously in another thread.
  • If the NEX function that is not thread-safe is called from multiple threads when you are not in thread-safe mode, a warning is now issued in the debugging log, and execution stops with an assertion failure at the same time. This mechanism is enabled outside of release builds. Also added CriticalSection::SetEnableDetectRaceCondition() and CriticalSection::GetEnableDetectRaceCondition(). This function disables the check mechanism for this thread conflict. The function can only be used for test purposes.
  • Added String::GetLiteralStringAs() and String::LiteralStringHolder. This function can be used to easily convert from a String object to a char or char16_t.
  • Revised the function so that memory allocation is not performed when storing a short string in String. The behavior of String::String(String::NoAllocTag) is now the same as for the default constructor. Previously, memory allocation occurred when the String object was replaced, but memory allocation no longer occurs if the object is replaced by fewer characters than the buffer that is already allocated.
  • Added String::ShrinkToFit(). It truncates the internal buffer to the length of the string.
  • Added String::Capacity(). It returns the length of the string (not including the terminating character) that can be stored without reallocating memory.
  • While the String::Reserve() function previously included the terminating character when specifying the length, the specifications have been changed to omit the terminating character.
  • The String::SetBufferPtr() function is now private.
  • The String::SetStringToPreReservedBuffer() function is now private.
  • While Bind(), the class that inherits ServiceClient::Bind() and ServiceClient, could only be called one time for each object, Credentials has now been changed so that it is possible to call Bind() again to rebind Credentials that have already been bound. In addition, Unbind() can now be called without calling Bind().
  • Reduced the CPU load for Scheduler::Dispatch(). The CPU time is reduced by approximately 30% during routine calls.
  • Added SingleStepJob::OnCancelled(). If SingleStepJob::OnCancelled() is overridden, it will be called when asynchronous processing is canceled.

Matchmaking

  • When using the keywords feature for auto-matchmaking, you can now only create one matchmaking session for the same keyword. Specify AUTO_MATCHMAKE_OPTION_UNIQUE_GATHERING_BY_CODEWORD in AutoMatchmakeParam::SetAutoMatchmakeOption() to use this feature.
  • The constant name for the maximum size of the principal ID list that can be specified when searching for matchmaking sessions by principal ID was inappropriate, so the previous MAX_MATCHMAKE_BROWSE_SIZE_BY_PARTICIPANT was replaced with MAX_PRINCIPALID_SIZE_TO_FIND_MATCHMAKE_SESSION. The original MAX_MATCHMAKE_BROWSE_SIZE_BY_PARTICIPANT is now private, but can still be used.
  • Made MatchMakingClient::GetParticipantsURLs() public. This function is meant to be used with VSocket::ProbeStations().
  • Previously, MatchMakingClient::GetParticipantsURLs() would get an empty StationURL list if no gathering existed, but it now returns a QERROR(RendezVous, SessionVoid) result in such cases. While the function will get the result even if is not a participant in the gathering, the result will be QERROR(RendezVous, PermissionDenied) when it is not a participant in the gathering.
  • The various MatchMakingClient::EndParticipation(), MatchMakingClient::GetDetailedParticipants(), MatchMakingClient::GetSessionURLs(), MatchMakingClient::MigrateGatheringOwnership(), and MatchmakeExtensionClient::UpdateProgressScore() functions now return QERROR(Core, InvalidArgument) as the result when INVALID_GATHERINGID is passed as the argument. In this case, the process will be stopped by an assertion failure for all cases other than the release build. The previous behavior was to return false and not start asynchronous processing.

DataStore

  • You can now specify NULL for the dataId parameter in the DataStoreClient::PostObject() function.
