NintendoSDK-NEX for NX 4.6.9

Introduction

This package is the expanded communication library for the NX version of the NintendoSDK. It includes features for matchmaking, ranking, and data stores. (NEX is an abbreviation for network extensions.) In the following, we will use NX NEX to refer to the NintendoSDK NEX for NX. NX NEX includes both 32-bit and 64-bit binaries for each of the Windows, NX on Windows, and NX versions. To view the revision history for the library, see Revision History.

Note:

The Windows and NX on Windows versions will only be available for development. For those versions, users will temporarily log in to each game server in advance using predefined user names and passwords.

Note:

This library uses encryption technology.

System Requirements

To build NX NEX, the version of Visual Studio supported by the version of Nintendo SDK that you are using must be installed. The NintendoSDK itself and NintendoSDK VSI for NX are required to build the Windows version. The NintendoSDK NX Add-On is required to build the NX on Windows version. The NintendoSDK NX Add-On and NintendoSDK Clang for NX are required to build the NX version.

Verified Operating Environment

NintendoSDK 18.3.0 NX Add-On 18.3.0

The versions of the compiler and VSI are the same as the environment for confirming SDK behavior. For more information about the status of confirming behavior in the newest NintendoSDK, see the latest information on the download site.

Installation

Extract this package to a directory with a name that includes neither spaces nor Japanese characters. For the remainder of this document, this directory is referred to as NINTENDO_SDK_NEX_ROOT.

The wizard file for Visual Studio is copied to the NintendoSDK console when you install from NDI. That wizard file will be copied to the directory that the NINTENDO_SDK_ROOT environment variable points to when you run InstallWizard.bat, within the root directory, after installing from the ZIP file.

How to Use

Set this directory path as the NINTENDO_SDK_NEX_ROOT environment variable and include nex.h. You do not need to set this environment variable if NINTENDO_SDK_ROOT has been set as an environment variable in NintendoSDK and the NintendoSDK\ and NintendoSDK-NEX\ directories have been configured in parallel as follows.

  • C:\Users\user_name\Documents\NDIEnv\environment_name\NintendoSDK\
  • C:\Users\user_name\Documents\NDIEnv\environment_name\NintendoSDK-NEX\

If you plan to manually specify the include path and the libraries path, use the following paths. Use the Develop version library for the NX version Debug build. - $(NINTENDO_SDK_NEX_ROOT)\Include - $(NINTENDO_SDK_NEX_ROOT)\Libraries

For more information about libraries that must be linked to use the various NEX features, see the sample demo settings.

Running Sample Demos

Logging In to the Game Server

The current version of NX NEX provides the following three methods for logging in.

  • Using a specified game server ID and access key
  • Using an NSA ID token
  • Specifying the user name and password configured in advance on each game server
Logging In by Specifying the Game Server ID and Access Key

This is applied in the sample demo's default state. In this version, this method only supports the NX version. The Windows version is not supported. You must also configure the application ID for sample demos (0x0100289000012000) for the image that you want to run.

Metadata will be configured within the $(NINTENDO_SDK_NEX_ROOT)\Samples\Resources\SpecFiles\ folder when building a sample demo in the NSPD format. For more information about metadata settings, see Writing NMETA Files in the NintendoSDK Documents.

Using an NSA ID Token

Edit the following file to enable the NEX_DEMO_ACCOUNT_SUPPORT macro. When you do this, even Windows applications will try to log in to NGS without using the nn::nex::NgsFacade::DebugLoginDirect() function.

  • NintendoSDK-NEX\Samples\Applications\NEX\common\NexDemoUtil\NnSdkNexUtil.h
Logging In Using the User Name and Password Set in Advance for Each Game Server

Use this method only for the Windows version.

After requesting a game server for each application via OMAS, you must ask Nintendo to issue a user name and password for each application (for each game server). For more information about the request method, see the following section.

https://developer.nintendo.com/group/development/g1kr9vj6/tech-info?articleId=310744258

Note:

As a security measure, you cannot use this method to log in to the game server accessed by the sample demo. In addition, the method of logging in to NGS (the NEX game server) using the nn::nex::NgsFacade::DebugLoginDirect() function was deprecated in June 2021, as announced in Removal of login mechanism that takes a login user name when using NEX on Windows.

In the Windows version, you can set the game server URI, the access key, the login user name, and the password by specifying the -uri, -key, -user, and -pass runtime arguments.

You can use the following values for the login user name and the password.

  • Login User Name: ID issued by Nintendo + random number from 1 to 9999
  • Password: Password issued by Nintendo

Also, this method can be used for the NX version, but not for the retail version. In the NX version, use the log in method described in Logging In by Specifying the Game Server ID and Access Key.

Sample Windows Version Run:

Rmc.exe -uri "https://gXXXXXXXX-dd1.s.n.srv.nintendo.net/" -key "Please specify your access key" -user testuser_1 -pass "Please specify your password"

XXXXXXXX above is a zero-padded 8-digit hexadecimal number used for the game server ID.

Environment Variables When Running a Windows Version

In the Windows version, the environment variable can be used instead of the parameter. Run after setting the game server URI, access key, login user name, and password to environment variables RV_TEST_URI, RV_TEST_KEY, RV_TEST_USER, and RV_TEST_PASS.

The default is identical to when specifying environment variables, as follows. There may be cases where identical user names are chosen because user names are randomly selected, and it is possible that users logged into the game server with the same user names will be disconnected. We recommend that you clearly specify the user name and password, except when running a sample demo.

set RV_TEST_URI=https://gXXXXXXXX-dd1.s.n.srv.nintendo.net/
set RV_TEST_KEY=Please specify your access key
set RV_TEST_USER=<ID issued by Nintendo> + "random number from 1 to 9999"
set RV_TEST_PASS=<Password issued by Nintendo>

HTTP proxy settings are required, depending on the environment, for connecting with the game server. When setting HTTP proxies, reference a Nintendo SDK manual (for example, the manual for SettingsManager.exe).

String Notation in Sample Demos

Strings are enclosed in NEX_T() in the sample demo program code to switch to wide characters based on the environment. (For example, NEX_T("ABC").) In NintendoSDK NEX, NEX_T("ABC") becomes "ABC" regardless of the character encoding set (Unicode, MBCS) in Visual Studio.

Notes

Build Types and Link Libraries
When linking NEX libraries, link the NEX library with the same build type as the build type of the application that uses NEX. Applications may not run as expected if the same build type is not used.
The Character Encoding That Can Be Used With NEX
NintendoSDK NEX uses the UTF-8 format internally. Because the String class constructor can take values using the wchar_t type, this can be used to convert Unicode strings defined with wchar_t to UTF-8.
Updating the Game Server
The NEX library checks the server version when a user logs in to the game server. If the server version is earlier than the version required by the library, it is not possible to log in to the game server. Accordingly, if the NEX library used by the application is updated, the game server also must be updated. Make the game server update request from OMAS. (Game servers do not update automatically.)
Data Units
Unless otherwise specified, the unit when talking about kilobytes of is KiB (1024 bytes). Similarly, the unit for megabytes is MiB (1024 * 1024 bytes).
