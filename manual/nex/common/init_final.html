2. NEX Initialization and Finalization

2.1. Preparing for Initialization

Complete the following steps before initializing NEX.

  • Initialize nn::nifm, submit a network use request, and then verify that this has been accepted by the system.
  • Initialize nn::socket and libcurl.
  • Initialize nn::account.

2.2. Initialization

Initialize NEX as follows.

  • Set the functions that NEX uses to allocate and deallocate memory, by using the MemoryManager::SetBasicMemoryFunctions() function.
  • Set the thread mode (Core::SetThreadMode()).
  • Generate the NEX Core object (call nn::nex::Initialize() or generate various client instances such as NgsFacade, VSocket, and MatchmakeExtensionClient).

The NEX Core object is generated either when nn::nex::Initialize() is first called, or when one of the various client instances such as NgsFacade, VSocket, and MatchmakeExtensionClient are first generated. Although it is not required, we recommend calling nn::nex::Initialize(true) to prevent situations such as the Core object being generated unintentionally, and the thread mode settings not being applied.

For more information about initialization, see 3. Memory Management and 4. Initialization Settings (Thread Models, Exclusive Control, Log Output).

Note:

You must create an instance of NgsFacade before you create a service client instance (for example, an instance of RankingClient). If you do not follow this procedure when creating instances, internal inconsistencies will be detected when nn::nex::Finalize(true) is called and finalization will fail.

2.3. Finalization

Use the following procedure to finalize NEX.

  • Release the NEX Core object (call nn::nex::Finalize(), and destroy all of the client instances, such as NgsFacade, VSocket, and MatchmakeExtensionClient).
  • (Optional) Clear the settings of the functions that NEX uses to allocate and deallocate memory (call MemoryManager::SetBasicMemoryFunctions(NULL, NULL)).
  • (Optional) Runs processes after finishing using the libraries that were initialized to prepare for initializing NEX.

Call Core::GetInstance()->SetTerminateImmediately(true) to speed up finalization during shutdown, sleep mode, or when not connected to the network, and to make NgsFacade::Logout() execute faster. However, because standard disconnection is not performed, the local terminal sometimes appears to be suddenly disconnected from the network (from the perspective of other peers) because of a keep-alive timeout. For this reason, do not set this mode for normal termination sequences. After Core::SetTerminateImmediately() has been called, all functions that communicate with the server will fail.

Note:

You can only use the Core::SetTerminateImmediately() function if you are destroying an entire NEX session when shutting down, entering sleep mode, or when you are not connected to a network.
