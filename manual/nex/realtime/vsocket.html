1. VSocket

1.1. VSocket Overview

VSocket is a UDP socket-like interface to a low-level communication library. VSocket allows you to use third-party network engines for peer-to-peer communication between clients while continuing to take advantage of NEX server features, NAT traversal, encryption, and spoofing detection. We expect third-party network engines to be updated to use the VSocket API instead of the socket API.

Like UDP, VSocket is a connectionless protocol that does not guarantee delivery or ordering. Because most networked devices are located behind a NAT router, NAT traversal must be done before starting VSocket communications. For more information about the NAT traversal feature, see also 2. Applications must send keepalive signals to preserve routers’ NAT table entries along the path between two devices.

You can send up to 1,250 (VSocket::MAX_DATA_SIZE) bytes. You cannot communicate with an independent server that is not using the VSocket library. That library is necessary for spoof detection.

Note:

An online battle system that uses VSocket and NEX matchmaking was implemented with Unreal Engine 4. For more information, contact Nintendo. Unreal Engine 4 is a trademark or registered trademark of Epic Games, Inc.

1.2. Notes

Note that the following must be implemented when using VSocket.

  • NAT traversal must be done before starting VSocket communications. Call ConnectivityManager::StartNATSession() and VSocket::ProbeStations() to perform NAT traversal before starting communication. Call ConnectivityManager::StopNATSession() after communication has completed.
  • You must call ConnectivityManager::StopNATSession() and ConnectivityManager::StartNATSession() again, every time a VSocket object is destroyed, when you change opponents.
  • NAT table entries that were created using NAT traversal, for any NAT devices that remain without communication for a long period of time, are removed. As a result, communication via VSocket will not continue. Make sure that communication occurs for all VSocket partners at least once every ten seconds to avoid losing the ability to communicate. Send a keep-alive packet when a state with no communication continues.
  • You cannot use multiple P2P sessions from the same device. ConnectivityManager::StartNATSession() cannot be called for multiple clients even if several NgsFacade objects are prepared and you are using multiple clients. When multiple users participate in real-time communication from the same terminal, have them do so from a single representative client, and also use that client as the representative for communication processing.

The VSocket transmission buffer is managed by the packet buffer manager, using a fixed-length memory pool. When the packet buffer runs out of space, VSocket::SendTo() returns VSocket::PacketBufferFull. When VSocket::PacketBufferFull occurs, call Scheduler::Dispatch() and either wait briefly before trying to send the data again, or increase the packet buffer. For more information about the packet buffer, see Managing Packet Buffer Memory.

1.3. Implementation

For more information, see the VSocket sample demo. The sample demo offers examples of creating full-mesh network topologies and server-client (star) network topologies.

1.3.1. Host Migration

To continue supporting matchmaking and peer-to-peer (P2P) sessions even after a P2P session, created by an application, experiences a host device's disconnection, call MatchMakingClient::UpdateSessionHost() from the new host device. You must then update the host data that was added to the game server.

Note:

To get information about devices connected by VSocket, use the MatchMakingClient::GetSessionURLs() or MatchMakingClient::GetParticipantsURLs() function. Specifically, device information retrieved with MatchMakingClient::GetSessionURLs() is for devices that have created the most recent matchmaking session. After the hosting device has left a peer-to-peer session, you can no longer get information with the MatchMakingClient::GetSessionURLs() function, and it is no longer possible to join the peer-to-peer session. MatchMakingClient::UpdateSessionHost() is the function to register or update new host information.

1.3.2. Error Handling

When NAT traversal fails using VSocket::ProbeStations(), you can get QERROR(Transport, NatTraversalError) with the CallContext::GetOutcome() function. When this is the case, get the network error code, pass it to the error viewer applet, and then shut down communication. (For information, see Handling Asynchronous Processing Errors.)
